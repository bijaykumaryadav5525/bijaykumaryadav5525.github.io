📄 1. Executive Summary

Shai-Hulud was a self-replicating software supply-chain worm discovered in the npm ecosystem in September 2025. ReversingLabs first detected the cascading compromise on 15 September 2025, while the first known compromised package, rxt-authentication version 0.0.3, had been published on 14 September at 17:58:50 UTC. The incident was notable because it combined malicious package injection, automatic propagation, credential theft and exposure of private development resources within one attack chain. (ReversingLabs, 2025a; ReversingLabs, 2025b)

Unlike conventional malware that primarily spreads from one endpoint to another, Shai-Hulud used the software-development ecosystem as its propagation medium. A compromised npm maintainer account could be used to publish infected versions of other packages controlled by the same account. When developers or build systems installed an infected package, an npm postinstall lifecycle script executed a malicious bundle.js payload. The payload searched for high-value credentials and secrets, including npm, GitHub, AWS and GCP tokens, and used TruffleHog to broaden secret discovery. (ReversingLabs, 2025a; ReversingLabs, 2025b)

🤖 AI Executive Overview

Shai-Hulud represents a new generation of supply chain threats that leverages the trust relationships in software development:

  • Self-Propagating: Uses compromised accounts to spread automatically
  • Multi-Platform: Targets npm, GitHub, AWS, and GCP credentials
  • Persistent: Stolen credentials enable continued access even after malware removal
  • Scale: Hundreds of packages compromised within days
  • Sophisticated: Uses legitimate tools (TruffleHog) for malicious purposes

📚 2. Introduction

Modern software development depends heavily on open-source components. JavaScript applications commonly use npm packages directly and indirectly through transitive dependencies. This model allows developers to build applications quickly, but it also creates a large trust network in which a compromised package may execute code inside many unrelated environments.

Shai-Hulud showed how an attacker can turn that trust network into an automated propagation mechanism. Instead of relying solely on users clicking malicious links or executing suspicious files, the worm placed malicious code inside legitimate package versions. The installation process then became the execution trigger. (ReversingLabs, 2025a; ReversingLabs, 2025b)

The incident is particularly relevant to cybersecurity because developer workstations and CI/CD systems often contain credentials with access to source repositories, package registries, cloud platforms, deployment systems and other business services. A malicious dependency therefore has the potential to become an identity-compromise event and a software-delivery compromise at the same time.

🔍 Key Characteristics

  • Self-Replicating: Automatic propagation through npm packages
  • Credential Theft: Targets npm, GitHub, AWS, GCP tokens
  • GitHub Abuse: Creates malicious repositories and workflows
  • Exfiltration: Steals sensitive data and source code
  • Supply Chain Focus: Exploits trust in software dependencies

🎯 Why npm was Attractive

  • Large number of interconnected packages
  • Automatic dependency installation
  • Maintainer accounts with publishing rights
  • Developer environments with credentials
  • Rapid package distribution
📦 3. Background: npm and the Software Supply Chain

3.1 What is npm?

npm is the package-management ecosystem widely used by JavaScript and Node.js developers. Projects define dependencies in package.json and commonly use lockfiles such as package-lock.json to record resolved versions. During installation, npm processes package metadata and may execute lifecycle scripts associated with packages. (npm, 2026)

Lifecycle scripts are a normal part of npm functionality. npm documentation describes preinstall, install and postinstall events as part of the lifecycle for npm install. This capability is useful for legitimate build and setup tasks, but it also means that installing a dependency can cause code supplied by that dependency to execute in the local environment. (npm, 2026)

3.2 Software Supply-Chain Attacks

A software supply-chain attack compromises software, a package, a developer account, a build process or another component used to create and distribute software. The attacker then uses the trust already placed in that component to reach downstream users. (ReversingLabs, 2025a; Wiz, 2025)

MITRE ATT&CK classifies compromise of software dependencies and development tools under T1195.001. npm and other package ecosystems are specifically identified as potential supply-chain targets because dependencies can carry malicious code into consuming applications. (MITRE ATT&CK, 2026)

// Example: How npm lifecycle scripts work npm install // Triggers lifecycle scripts
preinstall // Runs before installation
install // Runs during installation
postinstall // <-- Used by Shai-Hulud to execute malicious code
🐛 4. What is Shai-Hulud?

Shai-Hulud is the name given to a self-replicating npm supply-chain worm first detected in September 2025. ReversingLabs described it as a "first-of-its-kind registry-native worm" because its propagation mechanism operated through npm packages and maintainer accounts rather than relying on a conventional network exploit. (ReversingLabs, 2025a; ReversingLabs, 2025b)

The name comes from the open-source repository associated with the malicious code and references the giant sandworms of the Dune universe. The name became a useful identifier for the incident because attacker-created repositories and branches also used Shai-Hulud-related naming conventions. (ReversingLabs, 2025a; ReversingLabs, 2025b)

🤖 AI Analysis: Worm Behavior

Shai-Hulud's behavior is significant because it represents a new class of malware that operates at the software development ecosystem level:

  • Registry-Native: Uses npm's own distribution mechanisms
  • Self-Propagating: Automatically spreads through package dependencies
  • Credential-Centric: Focuses on stealing development credentials
  • GitHub-Integrated: Uses GitHub for exfiltration and further propagation
  • Multi-Stage: Combines package infection, secret discovery, and data exfiltration

🔬 Core Capabilities

  • Package Infection: Inserts malicious code into legitimate packages
  • Automatic Propagation: Uses compromised accounts to spread
  • Secret Discovery: Uses TruffleHog to find credentials
  • GitHub Exfiltration: Creates repositories and workflows for data theft
  • Private Repository Exposure: Makes private repos public

⚠️ Impact Vectors

  • Credential Theft: npm, GitHub, AWS, GCP tokens
  • Source Code Exposure: Private repositories made public
  • CI/CD Compromise: Workflows hijacked for further attacks
  • Supply Chain Poisoning: Trusted packages become malicious
  • Persistent Access: Stolen credentials remain valid after cleanup
🔍 5. Discovery and Patient Zero

ReversingLabs reported that its researchers first detected the cascading compromise on 15 September 2025. The first known compromised package was rxt-authentication version 0.0.3, published on 14 September 2025 at 17:58:50 UTC. The maintainer account associated with that package was therefore described as the campaign's Patient Zero based on the available evidence. (ReversingLabs, 2025a; ReversingLabs, 2025b)

The exact initial compromise method was not conclusively established in the research. ReversingLabs noted similarities with other recent attacks against open-source maintainers, including techniques involving credential theft, social engineering and abuse of development workflows. (ReversingLabs, 2025a; ReversingLabs, 2025b)

⚔️ 6. Attack Overview

At a high level, the original Shai-Hulud attack can be represented as a seven-stage chain:

🔄 7-Stage Attack Chain

  1. Account Compromise: npm maintainer account is compromised
  2. Package Publishing: Malicious versions of packages are published
  3. Installation: Developers or CI systems install infected packages
  4. Execution: postinstall script executes malicious bundle.js
  5. Discovery: Payload searches for credentials and secrets
  6. GitHub Activity: Stolen credentials used for GitHub operations
  7. Propagation: Newly compromised accounts become additional propagation points

🌀 Feedback Loop

The most important characteristic is the feedback loop. In a traditional supply-chain attack, a malicious package may compromise many downstream users but stop there. Shai-Hulud could use credentials recovered from one victim to compromise additional packages, which could then infect more victims.

CRITICAL - Self-Replicating

🤖 AI Attack Analysis

Shai-Hulud's attack chain demonstrates advanced threat actor capabilities:

  • Lateral Movement: The worm moves between accounts and packages
  • Credential Harvesting: Actively searches for high-value credentials
  • Persistent Access: Stolen credentials provide continued access
  • Multi-Cloud: Targets AWS and GCP credentials for cloud access
  • Tool Abuse: Uses legitimate security tools (TruffleHog) maliciously
🔬 7. Technical Details

Initial Access and Account Compromise

The initial compromise of the first maintainer account remains an important uncertainty. ReversingLabs explicitly stated that the exact nature of the initial compromise was not known. Similar contemporary incidents involved phishing, social engineering and compromised development workflows. (ReversingLabs, 2025a; ReversingLabs, 2025b)

Malicious npm Package and postinstall Execution

The worm injected a malicious JavaScript payload into legitimate packages. ReversingLabs described the main malicious component as a 3MB+ JavaScript file named bundle.js. The infected package included a postinstall action that caused bundle.js to execute when the package was installed. (ReversingLabs, 2025a; ReversingLabs, 2025b)

// package.json with malicious postinstall {
  "name": "rxt-authentication",
  "version": "0.0.3",
  "scripts": {
    "postinstall": "node bundle.js" // <-- Malicious execution
  }
}

The technique exploited a normal npm feature rather than a software vulnerability. npm lifecycle scripts are designed to support legitimate package setup operations. The security problem arises when a trusted package contains a malicious lifecycle script, because the package manager itself becomes the mechanism that launches the payload. (npm, 2026)

Credential and Secret Theft

Credential theft was a central objective of Shai-Hulud. The malware searched for authentication material that could provide access to software-development and cloud environments. ReversingLabs specifically identified npm, GitHub, AWS and GCP tokens among the targeted credentials. (ReversingLabs, 2025a; ReversingLabs, 2025b)

🔑 Targeted Credential Types

  • npm publishing and authentication credentials
  • GitHub access tokens
  • AWS credentials and tokens
  • Google Cloud Platform credentials
  • Environment variables and other secrets
  • Secrets discovered in files and repositories through secret-scanning

TruffleHog and Secret Discovery

The Shai-Hulud payload used TruffleHog to increase its ability to locate secrets. ReversingLabs noted that TruffleHog can identify more than 800 types of secrets. The use of an established secret-scanning utility allowed the malware to search for credentials beyond a small hard-coded list of token locations. (ReversingLabs, 2025a; ReversingLabs, 2025b)

🤖 AI Technical Insight

The use of TruffleHog demonstrates a sophisticated attacker technique:

  • Tool Repurposing: Legitimate security tools are used for malicious discovery
  • Broad Coverage: TruffleHog detects 800+ types of secrets
  • Automated Discovery: No need to hard-code specific secret locations
  • Cross-Platform: Works across different cloud providers and services
  • Detection Challenge: Security teams must monitor for unexpected tool execution

GitHub Abuse and Data Exfiltration

Stolen GitHub access tokens enabled the malware to use compromised accounts for data collection and exfiltration. ReversingLabs reported that the malware created GitHub repositories named Shai-Hulud Repository and placed stolen information in a file called data.json. The data was double Base64-encoded before upload. (ReversingLabs, 2025a; ReversingLabs, 2025b)

📊 GitHub Behaviors

  • Created repositories with "Shai-Hulud" naming
  • Placed data.json with encoded stolen data
  • Created "shai-hulud" branches in existing repos
  • Added malicious GitHub Actions workflows
  • Made private repositories public with "-migration" suffix

🔍 Detection Opportunities

  • Audit repository creation events
  • Inspect unexpected repository contents
  • Monitor branch creation patterns
  • Review workflow file changes
  • Alert on private-to-public changes

🚨 11. Incident Response

🔍 11.1 Identify

  1. Determine whether any affected package versions were installed
  2. Identify developer machines, build agents and CI runners
  3. Review npm, GitHub and cloud credentials accessible
  4. Search GitHub for suspicious repositories, branches, workflows
  5. Collect package versions, hashes and relevant logs

⛔ 11.2 Contain

  1. Stop use of affected package versions
  2. Temporarily restrict package publishing where necessary
  3. Disable or isolate compromised developer and CI identities
  4. Restrict suspicious GitHub workflows and repositories
  5. Block known malicious destinations where appropriate

🧹 11.3 Eradicate

  1. Remove infected dependencies and restore known-good versions
  2. Rebuild affected development and CI environments
  3. Remove unauthorized workflows, branches and repositories
  4. Revoke and replace potentially exposed credentials
  5. Verify package integrity before resuming releases

🔁 11.4 Recover

  1. Restore development and CI operations from clean environments
  2. Reissue credentials using least-privilege scopes
  3. Validate software builds and release artifacts
  4. Monitor identity, package and GitHub activity for recurrence
  5. Document root cause and improve supply-chain controls

🤖 AI Response Analysis

Effective incident response for Shai-Hulud requires coordinated action across multiple domains:

  • Identity Security: Immediate credential rotation for all potentially exposed tokens
  • Package Management: Identify and remove malicious package versions
  • GitHub Security: Audit and clean up suspicious repositories and workflows
  • Development Environment: Rebuild from known-good sources
  • Continuous Monitoring: Enhanced monitoring for recurrence
🛡️ 12. Prevention and Mitigation

🔐 Critical Controls

  • MFA / Phishing-resistant authentication for maintainers
  • Short-lived and granular npm tokens
  • Trusted publishing / OIDC for CI/CD
  • Least-privilege CI identities

📦 Package Security

  • Dependency pinning and lockfiles
  • Software Composition Analysis (SCA)
  • SBOM for rapid identification
  • Install-script governance

🔍 Monitoring

  • GitHub branch and workflow protection
  • EDR and developer endpoint monitoring
  • SIEM correlation for integrated detection
  • Centralized secret management

🤖 AI Mitigation Strategy

Preventing attacks like Shai-Hulud requires a defense-in-depth approach:

  • Identity Layer: Strong authentication with MFA and short-lived tokens
  • Package Layer: SBOM, SCA, and install-script governance
  • GitHub Layer: Branch protection, workflow review, and audit logging
  • Endpoint Layer: EDR, behavioral monitoring, and process detection
  • Correlation Layer: SIEM integration for cross-domain detection
📝 13. Conclusion

The original September 2025 Shai-Hulud campaign demonstrated a major change in the way software supply-chain attacks can operate. The attacker did not simply place malware in an isolated package. The campaign used compromised npm publishing authority, package lifecycle execution, credential discovery, GitHub abuse and automatic republishing to create a self-propagating loop. (ReversingLabs, 2025a; ReversingLabs, 2025b)

The most important lesson is that software dependencies must be treated as part of the organization's security perimeter. Protecting production servers while leaving developer accounts, package registries, CI/CD credentials, GitHub workflows and cloud tokens insufficiently protected creates a major blind spot. (GitHub, 2025a; GitHub, 2025b)

Effective defense requires multiple layers: strong maintainer authentication, short-lived credentials, trusted publishing, dependency monitoring, software composition analysis, SBOMs, install-script governance, least-privilege CI/CD, GitHub monitoring, endpoint detection and rapid credential rotation. (GitHub, 2025a; GitHub, 2025b)

🤖 AI Final Analysis

Shai-Hulud should be remembered not merely as a malicious npm package incident, but as a demonstration of how the modern software-development ecosystem can become a worm propagation platform when trust, automation and excessive credential access intersect. (ReversingLabs, 2025a; ReversingLabs, 2025b)

🔑 Key Takeaways

  • Supply chain security: Every dependency is a potential attack vector
  • Identity security: Developer credentials must be protected like production secrets
  • Zero-Trust: Never trust packages or maintainers implicitly
  • Defense in depth: Multiple layers of security are essential
  • Continuous monitoring: Detect and respond to supply chain threats proactively
